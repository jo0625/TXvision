## 指令与反馈的曲线时差

在断流前有有效指令的区间内，按 20 ms 网格比较转发目标与后续反馈，
排除首尾一秒和目标已超过 150 ms 未更新的采样；扫描 0 至 1 秒时移并最小化角度 RMSE。
目标角使用零阶保持，反馈角使用相邻样本插值。

- yaw 的整段最优时移约 **80 ms**；分成若干八秒窗口后约 80 至 140 ms。
- pitch 的整段最优时移约 **60 ms**；分段约 60 至 80 ms。

这是“上位机转发目标到反馈曲线变化”的近似跟随时差，含通信、控制和机械运动影响。
反馈约 20 Hz，没有真实写入时刻或电机到位确认，不能解释成精确单程串口延迟，
也不包含相机曝光到视觉目标生成之前的耗时，更不能代表每一次变向。

## 两个独立的待处理问题

### 1. 目标指令存在间断

断流前下位机反馈连续，有效指令却出现十次超过 150 ms 的间隔。
这些间隔中有 tracking=false / invalid_input_command，转发器没有把无效零角度发送出去。
例如约 21.536 至 22.044 秒，间隔中的 16 条检测均非空，但 16 条跟踪消息仅 1 条 tracking=true。
另有间隔伴随检测为空；不能一概归因于串口或模型漏检。

后续需要结合目标是否离开视野，以及候选匹配、跟踪重新初始化的证据定位。
本轮只有检测数量和 tracking 标志，没有保存所有候选三维坐标，不能单凭这些计数确定具体匹配失败原因。
本次不凭空调整阈值。

### 2. 第 40.70 秒后 COM3 不再提供反馈

- 最后一条反馈序号 25635，下位机时间戳 1283891 ms；最后一次有效转发在第 40.662 秒。
- 旧通信桥状态为 connected=true、feedback_alive=false、command_active=false，状态发布仍在运行。
- Windows usbipd 列表仍显示 COM3；PnP Status=OK、ConfigManagerErrorCode=0。
- 停止旧桥后，只读诊断无法重新打开 COM3；独立 Windows SerialPort.Open 同样失败：
  `System.IO.IOException`, `0x8007001F`, `A device attached to the system is not functioning.`
- 因而“设备仍出现在列表中”不能证明串口可以使用。故障已涉及 Windows 串口/USB/设备交互层，
  目前不能区分主机驱动、USB链路或下位机固件/USB状态，也不能据此直接要求重烧固件。
- 约同一时刻观察到 WSL 系统时间向前校正约 1.014 秒，稍后还有两次向前校正。
  这是时间相关证据，不足以证明校时导致设备 I/O 故障；本轮未复现旧的向后校时暂停后补发模式。
- 姿态反馈中断后，动态 TF 停止更新，跟踪器因缺少相应时刻的变换丢弃图像消息，
  watchdog 发布 tracking=false；因此后半段跟踪消息缺失不能直接称为检测算力不足。
- 断流后检测也曾出现约 2.10 和 2.16 秒的输出间隔；相机日志有取图超时。
  这些异常保留在原始记录，尚未确定与 COM3 故障的因果关系。

本轮先停止发令、保留证据。需要恢复设备通信后再决定后续验证，不自动重启云台跟随。
