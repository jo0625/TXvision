# RoboMaster 自瞄数据、模型版本与测试规范总结

更新时间：2026-07-27

## 1. 为什么之前容易混淆

项目里同时存在三套编号，它们含义不同，不能一一对应：

| 类型 | 示例 | 含义 |
|---|---|---|
| 原始视频编号 | 01、02、03……10 | 数据来自哪一段视频 |
| 数据集版本 | dataset v4、v5、v6、v8 | 某个阶段的数据组合及 Train/Val/Dev 划分 |
| 模型版本 | model v2、v3……v8 | 某一次训练得到的模型 |

例如，`model v7` 并不是“使用视频 07 训练的模型”。它表示第 7 版模型实验；该模型实际使用的是当时整理好的数据集版本。

模型版本和数据集版本也不必相同。例如，模型 v7 可以使用 dataset v6 从官方预训练权重重新训练。

## 2. 数据不会在训练一次后被“用完”

训练数据可以在后续模型中继续使用。新的模型版本通常采用累积方式：

```text
原有训练数据
+ 新增正样本或负样本
+ 修正后的标签
= 新的数据集快照
→ 训练新的模型版本
```

因此，01、02、04 在 v4 中使用后，仍然可以继续用于 v5、v6、v7、v8。后续版本并不是只使用最近新增的视频。

## 3. Train、Val、Dev、Final Test 的分工

| 分组 | 作用 | 能否重复使用 |
|---|---|---|
| Train | 更新模型权重 | 可以反复训练 |
| Validation | 选择最佳 epoch、观察训练是否过拟合 | 可以重复使用 |
| Dev benchmark | 比较不同模型、选择 `conf`、分辨率和后处理参数 | 可以反复测试和调参 |
| Final blind test | 所有参数冻结后的最终验收 | 原则上只使用一次 |

“测试污染”不是指视频文件被修改，而是指看过测试结果以后，根据结果修改了模型、数据、阈值或后处理规则。

## 4. 当前建议的数据职责

```text
Train：01、02、04、07、08、09、10，以及训练硬负样本
Val：05
Dev benchmark：06
Legacy holdout：03
Final blind test：以后提供的全新视频 11
```

具体说明：

- 05 用于训练过程中的验证。
- 06 已经反复用于比较 v2、v4、v5、v6、v7 等模型及选择置信度，因此属于开发测试集，可以继续反复使用。
- 03 没有人工标签，也没有进入训练或 v4–v7 的定量评估，但早期存在 v0–v2、多种置信度的推理视频和 compare 图。因此它可以作为历史保留评估集，但不应描述成严格“从未看过”的盲测集。
- 11 应当在模型、阈值和后处理全部冻结后才提供并评估。

## 5. 模型迭代关系

历史过程可以简化理解为：

```text
v0–v2：早期模型，主要使用 01、02，后来增加 04
v3：加入或使用 05 的早期实验
v4：重新按完整视频划分，Train=01/02/04，Val=05，Dev=06
v5：在原数据基础上增加文字、Logo、屏幕等硬负样本
v6：继续增加视频 07、08
v7：使用当时的完整数据，从官方预训练权重重新训练
下一版：在既有训练数据基础上继续加入审核后的 09、10
```

这里的 v 表示模型实验的迭代次数，不表示某一段视频，也不表示旧数据已经停止使用。

## 6. 什么时候需要新测试视频

不需要每训练一个新版本就寻找新测试视频。

可以一直使用 05 和 06 开发模型：

```text
训练 v8
→ 在 05/06 上评估
→ 修改数据或参数
→ 训练 v9
→ 再在 05/06 上评估
```

只有以下过程需要新的最终测试视频：

```text
冻结模型和全部参数
→ 在视频 11 上最终测试
→ 根据视频 11 的结果继续修改模型或参数
```

一旦根据 11 的结果继续调整，11 就变成了新的 Dev 数据。下一次严格的最终验收需要全新视频 12。

如果测试 11 后不再修改模型，而是直接记录结果或发布，则不需要再寻找新视频。

## 7. 推荐的正式流程

1. 审核并固定训练标签，记录每段视频的图片数、空样本数和目标数。
2. 按完整视频划分数据，禁止同一视频的相邻帧跨 Train、Val、Dev 或 Test。
3. 使用 Train 训练候选模型。
4. 使用 05 选择训练 checkpoint。
5. 使用 06 比较模型并选择 `conf`、`imgsz`、NMS 和关键点过滤规则。
6. 冻结模型权重、参数、预处理和后处理代码，并保存 SHA-256 与配置清单。
7. 冻结完成后再提供全新视频 11。
8. 在不查看模型预测的情况下人工建立 11 的真值标签。
9. 使用冻结模型在 11 上评估一次。
10. 如果根据结果继续开发，则把 11 降级为 Dev，并为下一次正式验收准备视频 12。

## 8. 建议统一命名

为了避免再次混淆，后续建议使用：

```text
原始视频：video_01、video_02……
数据集快照：dataset_v8
训练模型：model_v8
开发测试：dev_video_06
历史保留测试：legacy_video_03
最终盲测：final_video_11
```

不要再使用 `final_test_06` 之类与实际职责不一致的目录名；如果暂时不能重命名，应在文档和 manifest 中明确它实际属于 Dev benchmark。

## 9. 对 AI 的约束

- 03 和 06 禁止加入训练。
- 模型、阈值、分辨率和后处理只能根据 Train、05 和 06 决定。
- 任何数据集构建都必须输出数据来源和划分清单。
- 必须区分“已验证事实”和“原因推测”。没有对照实验时，不得声称已经确认灾难性遗忘、数据不足或某个参数是唯一根因。
- 修改标签前必须备份；修改后必须核对类别、四个角点、目标数量和格式是否保持一致。

## 10. 核心结论

```text
训练数据可以在多个模型版本中重复使用。
Dev 视频可以反复测试和调参。
只有最终盲测视频具有一次性验收性质。
如果根据最终测试结果继续修改模型，就需要新的最终测试视频。
```
