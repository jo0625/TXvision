# 0.5度目标保持的完整链路测试（2026-09-23）

## 结果：已启动，断流中止，未完成三分钟

用户要求开始完整测试，并确认已切换视觉模式、装甲板到位。
准备检查确认模式6、连续检测非空、预览角度有效；先提示即将启用云台，
再启动 `--duration 180 --start-delay 8 --angle-deadband-deg 0.5` 的测试记录器。
收到 TEST_STARTED 和 command_active=true 后，明确通知用户正式开始三分钟。

最后一条下位机反馈出现在记录第 **30.933秒**。
监测程序发现反馈超过1秒未更新后，自动向转发器发送SIGINT；记录数据覆盖约32.343秒。
转发器退出时发布无效指令。已立即通知用户停止移动装甲板、切回遥控或失能。
随后停止本轮双向通信服务，不再自动重连；没有追加运动测试。

本轮证实0.5度保持规则实际生效，但不能作为三分钟稳定性验收通过，
也不能仅凭这段运动数据认定机械抖动或变向卡顿已改善。

## 条件

- 使用现有冻结候选模型、gray140候选配置和临时手眼外参。
- 相机设定30 FPS，1440x1080 BayerRG8，曝光3000 us、增益12 dB。
- 调试图独立进程、960x720、上限30 Hz，RViz保持开启。
- Windows COM3双向通信，115200；通信桥I/O定时器使用单调时钟。
- 仅在测试转发器中启用每轴0.5度保持；达到阈值更新，目标失效清空保持值。
- 保持角度时仍转发有效消息，串口发送率设置仍为50 Hz。该限制不减少通信包频率。

最后一条反馈之后约31ms还转发过一条当时反馈仍新鲜的有效目标，
因此全记录有效转发总数为695条。上述有效区间内反馈没有超过150ms的间隔，
随后发生的是持续断流。

原记录器summary仍用计划180秒计算平均频率，因此其4.97 FPS、3.18 Hz等值不代表本轮实际运行速率。
原始记录保留；本表与派生analysis.json均从rows按有效区间重算。
本轮姿态、目标动作和主机运行状态与上轮不完全相同，不能将速率差直接归因于0.5度过滤。

## 0.5度规则的实际效果

将每条转发命令与同次回调保存的原始有效预览角度配对，共695条：

| 项目 | yaw | pitch |
| --- | ---: | ---: |
| 保持旧目标、未采用本次微小变化的次数 | 367 | 434 |
| 占有效转发比例 | 52.81% | 62.45% |
| 原始目标与保持后目标的最大差 | 0.49903度 | 0.49728度 |

两轴同时保持的消息为237条。保持期间仍持续转发，没有因为角度未更新而停止通信心跳。
这些数字证明规则生效，不等于“抖动减少53%/62%”；实机改善需要结合运动状态和反馈评价。

## 当前仍存在的问题

### 目标失效造成的停发

断流前有效转发已有7次超过150ms的间隔，对应跟踪失效或无效输入。
最长为第26.068至28.567秒，约2.498秒：其中69条检测消息仅5条非空，
69条跟踪消息仅1条tracking=true。不能把这段停发当作0.5度保持造成，
也不能在没有画面可见性标注的情况下直接称为模型漏检。

第29.913至30.132秒、30.528至30.743秒另有短暂跟踪失效，
其间检测均非空。缺少完整候选位姿，尚不能确定是哪一项跟踪匹配条件导致。

### Windows串口再次失效

通信日志保留了以下顺序：

1. 一条 `Windows rejected expired command`。
2. `Windows serial write acknowledgement timed out`。
3. `Command expired before Windows write`。
4. Windows辅助进程报告设备不能正常工作，包含 `System.IO.IOException`，通信连接关闭。
5. 桥接程序约一秒后重新打开COM3，但没有恢复有效反馈；随后人工停止该服务。

本轮独立观察记录中没有检测到超过100ms的系统时间相对单调时间突跳。
这不能证明所有时钟问题已解决，但不能再把本次设备I/O错误直接解释为原先的时钟回拨暂停。

两轮主动发令的短段都出现了持续反馈中断，先前只读接收曾连续运行。
这是优先检查双向读写、USB链路和电控USB固件状态的依据，尚不足以确定故障属于哪一端。
0.5度保持只改变目标角，不修复设备I/O故障。
