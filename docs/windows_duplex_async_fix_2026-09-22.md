# Windows双向串口异步修复（2026-09-22）

## 原因

三分钟动态跟随期间，检测保持约29.90 FPS，但下位机反馈出现7个约1秒空窗。旧实现对每条控制指令依次执行WSL到Windows时钟握手、COM3写入和同步写确认等待。串口节点使用单线程ROS执行器，因此等待和重连期间也停止读取反馈。

## 修改

- 连接建立时检查对时通道，Windows随后每20 ms发送自己的单调时钟；命令使用最新Windows时间样本加上剩余有效期，不再用WSL累计运行时间推算Windows时间。最初的“只对时一次”版本在后续实测中失败，见下文。
- WSL侧最多保留一条正在发送的指令和一条最新待发指令；新目标替换尚未发送的旧目标。
- 写确认改为轮询状态机，ROS读取反馈时不等待确认。
- 保留从ROS命令到达时刻计算的100 ms新鲜度，Windows写入前仍拒绝过期指令。
- 单条写确认超时只丢弃该条指令，不关闭COM3；辅助进程退出、真实写错误或帧协议错误仍触发重连。
- Windows侧待处理队列满时保留最新请求，避免旧目标排队。

## 时钟修正与验证

在独立Windows辅助进程和内存串口上重新对时，约5.09秒内两系统时钟映射差变化约83 ms。初版把启动时的Windows时间加上WSL运行时长来生成截止时间，长时间连接后会积累误差；启动后立即发送的旧测试未覆盖此情况。

修正为Windows每20 ms提供新时间样本，发送截止时间取“最新样本 + 该条命令剩余有效期 - 2 ms”，不外推两系统的累计运行时间。样本传输延迟只会缩短有效期；超过100 ms未收到样本时等待新样本，原命令仍按原期限过期。保留异步收发，新增时钟消息不触碰机器人串口。

- 新增4项回归：模拟20分钟连接后的正/负映射偏差；禁止累计WSL时长扩展截止时间；缺失时钟样本时拒绝发令且反馈仍能接收。
- 修正前长连接用例失败，修正后通过。
- 包内94个pytest用例全部通过，无失败、错误或跳过；构建通过。
- 12秒Windows内存串口连续测试：585条提交、585条写入确认、0失败、586条反馈（含初始反馈）；发送调用最长1.19 ms，辅助进程保持运行。
- 上述持续写入验证未连接机器人，不证明实机跟随已恢复。修正版仍需短时实机确认。
